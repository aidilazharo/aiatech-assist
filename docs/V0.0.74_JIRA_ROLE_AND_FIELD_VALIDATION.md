# ATGV v0.0.74 — role-aware Jira preview and evidence-based fields

## Approved reference and limitations
TRM_Application_Req(2).xlsx contains Jira Import, Definition of Done, Decisions, Open Questions and Scope. It is a draft example and must be separately approved per project. The workbook does not identify actual Jira assignees and must never be treated as universal SDLC policy. No worksheet or sample value is embedded in the extension.

## Workflow and revisions
1. Upload or reupload the BR source, retaining source identity and immutable versions.
2. Regenerate affected requirements and Jira preview; previously published issue keys remain stable.
3. Resolve invalidated saved details, Jira identity conflicts, required field evidence and unresolved SDLC roles.
4. A BA reviews the current preview and approves before publishing. Already published work is updated only after approval.

## Role routing
- Distinguish a responsible SDLC *role label* from a real Jira *assignee account ID*.
- Task title cues make conservative suggestions; unknown or ambiguous technical tasks require role selection in Edit Jira item.
- All 18 ATGV role labels are available; the selected role is stored as revision-scoped Jira details.
- Creating an issue can add the role label. Adding a label during an update is allowed only if the existing issue has no conflicting role or unverified assignee. Conflicts block approval.
- Actual Jira account assignment continues to require a verified project roster, Jira assignability and permission checks. The system does not invent a user.

## Field validation
- Inspect create metadata for the target issue type and edit metadata for the existing issue.
- Map text from the approved BR and discovery only where supported; use approved issue-specific AC/DoD and an explicitly approved project DoD template.
- Unsupported optional fields stay blank. Required unsupported or missing fields block readiness.
- Avoid generic placeholders as Jira values. Preserve existing nonconflicting Jira field values and statuses.
- Test role mapping, draft-template rejection, required-field blocking and repeated publication reconciliation.

## Safety
No unrelated processes, existing Jira tickets, UI controls or source documents are removed. Historic Jira assignments, issue keys and comments remain unchanged.
