# Developer My Work — BR-to-Running-App Proposal

## Goal
Select an approved Business Requirement (BR). Let the AI produce implementation files, unit and integration tests, execute tests, repair bounded failures, and launch the approved project in a local server.

## Main screen
1. **Project & BR selector** at the top (approved revision, Jira link, architecture, approved branch, acceptance criteria count).
2. **One primary control:** `Generate & Run Application`; change to `Stop` while running. A simple setup readiness row displays required missing prerequisites.
3. **Compact stage timeline:** Analyze BR → Generate Code → Unit Tests → Build → Local Server → Verify Acceptance. Each stage reports state, elapsed time, errors and retry.
4. **Workspace tabs:** Code Changes (diff and file tree), Tests (pass/fail and coverage), Terminal (bounded logs), Preview (local URL with Open Browser), Evidence (traceability BR→files→tests).
5. **Footer:** commit/PR only after review; stop server; rerun failed stage; approval gates for database migrations and destructive commands.

## Orchestration
- Approved BR and discovered Jira tasks become a read-only versioned input; AI reads code from the configured project branch and approved technology stack.
- Validate repo and branch; create a dedicated task branch or isolated worktree, never write directly to main.
- Generate changed source and tests in tracked files, with reviewable diffs.
- Execute allowlisted stack commands from catalog manifests in the local checkout with a cancellable process manager; no arbitrary shell text generated by an LLM.
- If tests fail, allow a limited repair loop (e.g., 2 attempts) with diffs and full diagnostics.
- Launch server only after dependency, test and build gates succeed; detect a localhost URL using configured stack preview metadata and verify HTTP health.
- Completion requires acceptance checks; ready for review is not equivalent to deployed or Jira Done.

## Safety and recovery
- Never expose tokens in generated code, logs, or AI context; use environment variables and SecretStorage.
- Save a checkpoint per stage to resume after VS Code restart. Preserve user changes; warn on conflicts.
- Confirm destructive commands, schema changes and remote publishing separately.
- Display failed/unavailable operations as such—never mark test or server success based on AI text alone.
